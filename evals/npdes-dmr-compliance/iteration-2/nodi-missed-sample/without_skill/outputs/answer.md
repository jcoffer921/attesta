# Missed TSS sample at Outfall 002 (September, PA eDMR)

## Short answer

- **Do not enter a NODI code for the missing sample as if the whole parameter was not monitored.** You did collect one sample, so you have data. Report the one result you have.
- **Yes, collecting only one of two required samples is a monitoring/sampling frequency violation.** An autosampler failure is generally not a defense. It is reported, and you explain it in the comments.

## What to enter on the eDMR

1. **Report the one valid TSS result** you have in the appropriate fields (e.g., the Daily Maximum and/or Average Monthly value based on that single sample). A single sample is the average of the month by default, so the monthly average equals that one value, and the daily max is that value too.
2. **Number of Excursions / Sample Frequency fields:** In the "No. of Analyses" or "Samples Taken" field (PA eDMR has a sample count field in some parameter rows), enter 1, not 2. In the "Sample Frequency" item, the permit frequency stays 2/month.
3. **NODI code:** A NODI code (e.g., 9 = Conditional Monitoring Not Required, B = Below Detection Limit, C = No Discharge, 4 = Frozen, 6 = Weather, 8 = Not Required...) is for when no value is reported for a limit. It does not fit well here because you have a value. NODI Code **"9"** or similar should not be used to hide the missed sample. If there had been zero samples because of equipment failure, the typical option is to leave the value blank, and use the NODI "Q" (Not Sampled/Sample Not Collected) or whichever listed code applies in PA's eDMR code list ("Q" is used in many states for "Not Sampled"). Confirm the code list in PA DEP's eDMR user guide.
4. **Comments/Attachment:** Explain in the comment field: autosampler failure dates, that only 1 of 2 required samples was collected, corrective actions (repair/replacement, use of grab samples as backup), and the date it was fixed.

## Is it a violation?

- Yes. A permit that requires 2 samples/month sets a minimum monitoring frequency. Taking 1 sample is a failure to meet the monitoring requirement, which is a permit violation (a reporting/monitoring violation), separate from an effluent limit exceedance.
- It is not an effluent limit exceedance, since the TSS result you have can be compared to the limits normally. It is usually treated as a less severe violation, but it is enforceable under the Clean Water Act and PA Clean Streams Law, and DEP can cite it.
- Equipment failure is not an excuse by itself. The "upset" and "bypass" provisions don't generally cover a monitoring equipment malfunction. Permit Part A (Standard Conditions) requires proper operation and maintenance, and you should have backup (grab samples) when an autosampler is down. Where a composite is required, a grab sample may not substitute unless the permit allows it.

## What to do

- Report the single result, annotate the shortfall, and do not make up or estimate a second value.
- Contact the DEP regional office clerk/permit manager and, if useful, request a determination; some regions may accept a notice.
- Fix the sampler, document maintenance, and consider a spare unit or a grab-sample contingency in the SOP.
- Note that I am answering from general knowledge; verify the exact NODI code list and field names against the current PA DEP eDMR guidance and your permit's Part A/Part C.
